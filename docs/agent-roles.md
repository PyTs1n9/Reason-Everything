# Agent 工作流 · 岗位分工说明

> 把这条链路想象成一个**编译小组**：三个人并行读同一篇论文，各看一面；一个人专门挑错；一个人只负责排版装订。  
> 关键组织原则：**并行的三个岗位互不通信**——取证员不知道质疑员发现了什么，才会独立判断；只有对账员能看到全部。

```
        ↓                        ↓                        ↓
    取证员                    质疑员                    划界员
 （作者想让你信的）        （作者想让你略过的）      （这句话的适用边界）
        └────────────────────────┼────────────────────────┘
                                 ↓
                              对账员
                    （唯一能看到三份产出的人）
                                 ↓
                              编译员
                                 ↓
                         精读包（zip）
                                 ↓
                          主编（人工终审）
```

## 2. 岗位总表

| 岗位  | 站点  | 用模型  | 一句话职责                                  | 交付物                   |
| --- | --- | ---- | -------------------------------------- | --------------------- |
| 调度员 | 全链  | 否    | 决定谁先跑、失败重跑谁、预算够不够                      | 任务状态、checkpoint       |
| 拆解员 | S1  | 否    | 把 PDF 变成可定位的文本与锚点                      | `pages[]`、`Anchor[]`  |
| 取证员 | S2  | 是    | 抽出作者的主张，逐条回查原句                         | 支持卡 `ClaimCard[]`     |
| 质疑员 | S3  | 是    | 抽出局限、反常、未解释现象                          | 反证卡 `ClaimCard[]`     |
| 划界员 | S4  | 是    | 抽出适用条件，给出可用句式                          | 条件卡 `ClaimCard[]`     |
| 对账员 | S5  | 代码为主 | 机械校验 + 模型复核，决定放行还是打回                   | 评审报告 + `target_stage` |

## 3. 逐岗说明

### 3.1 调度员（Orchestrator）

- **做什么**：按固定 DAG 派活；记录每站输入/输出哈希；失败时只重跑该站及其下游；预算超限时停在当前站并保留已产出。
- **判定标准**：任一站失败，链路状态可定位到站；重跑不重复消耗已通过的站。
- **禁止**：不读论文内容，不判断质量，不"顺手改一下"。
- **失败时**：写 `checkpoint.json`，标 `partial`，等人决定续跑还是放弃。

### 3.2 拆解员（S1）

- **做什么**：用 pypdf 提取逐页文字与元数据；对空白页、加密页、损坏文件分别打标；把页文本建成可定位索引。锚点不在这里生成——此时还不知道要引哪一句。
- **判定标准**：页面文字提取率 ≥95%；空页必须显式上报，不允许"看起来解析成功了"。
- **禁止**：不做 OCR（扫描件直接转队列）；不猜测缺失文字。
- **失败时**：无文字层 → `ocr_pending`；加密/损坏 → `quarantine/` + 原因。

### 3.3 取证员（S2）

- **做什么**：只抽**支持性**主张；强制覆盖方法、结果、数字各至少一条；每张卡必须挂锚点（页码 + 原句 + 字符偏移）。
- **判定标准**：卡片 ≥10 张；定位率 100%（失败项标 `unverified`，不丢弃）；重复摘句合并。
- **禁止**：改写、翻译、缩写、补全原句；把"我认为"写进 `claim`。
- **失败时**：定位失败标 `unverified` 并排除出后续写作；一张都没通过则整站失败。

### 3.4 质疑员（S3）

- **做什么**：从 Discussion / Limitations 抽作者承认的局限、反常结果、未解释现象；每篇至少 1 条。
- **判定标准**：每篇 ≥1 条反证，或显式输出 `missing`；每条必须能回引原句。
- **禁止**：用常识替作者补局限；把"作者没提"写成"作者认为"；把审稿意见混进来。
- **失败时**：抽不到写 `missing` 占位（这是合法结果），**不允许编造**。

### 3.5 划界员（S4）

- **做什么**：按维度表（样本量 / 人群 / 任务 / 模型 / 数据集 / 时长 / 剂量 / 地域）抽取条件，并给出可用句式。
- **判定标准**：每张支持卡 ≥1 个条件维度，否则标 `scope_unknown`；条件必须来自原文，不能推断。
- **禁止**：用领域常识补条件；把"通常认为"写进条件。
- **失败时**：无维度 → `scope_unknown`；有维度但找不到原句 → 该维度丢弃并记录。

### 3.6 对账员（S5）

- **做什么**：先跑机械规则（页码、引文可定位、字段齐全、图注存在、条件必填、占位符、字数、锚点唯一），再让模型复核事实与越界；输出三态与 `target_stage`。
- **判定标准**：3 类注入错误 100% 拦截；误杀率 ≤5%；每条问题都写明回哪一站重做。
- **禁止**：把机械判失败的内容判为通过；改内容（它只能打回，不能代笔）。
- **失败时**：规则引擎自身异常 → 整篇 `blocked`，绝不"跳过校验继续打包"。

### 3.7 编译员（S6）

- **做什么**：把通过门禁的卡片渲染成 HTML/Markdown，打 zip，写 manifest（来源哈希、模型版本、提示词哈希、覆盖范围、签核位）。
- **判定标准**：包内成员齐全；`index.html` 双击可读、零外链；manifest 字段完整。
- **禁止**：修改任何内容；在缺字段时"凑一个默认值"。
- **失败时**：占位符缺失 → 拒绝打包；manifest 不全 → 拒绝打包。

### 3.8 主编（人工）

- **做什么**：只看两件事——`needs_review` 的论断是否可接受；`blocked` 的条目是否值得重修。
- **判定标准**：签字必须带理由与时间；抽检比例记入 manifest。
- **禁止**：不能把 `blocked` 直接改成 `passed`（必须先修复再重跑）；不能跳过抽检。
- **失败时**：不签字 → 包标记"未终审"，仍然可导出，但首页必须有明显提示。

## 4. 交接契约

| 从   | 到    | 交什么                    | 缺了会怎样         |
| --- | ---- | ---------------------- | ------------- |
| 拆解员 | 三站并行 | `pages[]` + `Anchor[]` | 三站全部无法开工      |
| 取证员 | 对账员  | 支持卡（含锚点）               | 门禁无法判断"有无依据"  |
| 质疑员 | 对账员  | 反证卡（或 `missing`）       | 无法发现"结论被过度推广" |
| 划界员 | 对账员  | 条件卡（或 `scope_unknown`） | 无法判断"是否越界"    |
| 对账员 | 编译员  | 通过门禁的卡片 + 报告           | 编译员拒绝打包       |
| 编译员 | 主编   | zip + manifest         | 无法签核          |

---

## 5. 三条组织规则

1. **三个取证岗位互不通信。** 共享上下文会让三者互相"对齐"，独立性消失——质疑员看到取证员抽了什么，就会只挑那些的毛病。
2. **只有对账员能说不，但不能改。** 有权打回、无权代笔；改内容必须回到产出它的岗位。
3. **模型只能降级，不能升级。** 机械规则判失败的，任何岗位都无权放行；这是整条链唯一不可协商的一条。

---

## 6. 谁不负责什么（防止职责漂移）

| 岗位  | 明确不负责                   |
| --- | ----------------------- |
| 取证员 | 不判断结论对不对，只负责"这句话确实在原文里" |
| 质疑员 | 不负责全面性，只负责"作者自己承认的问题"   |
| 划界员 | 不负责评价条件是否合理，只负责抽取       |
| 对账员 | 不负责改写，只负责判定与路由          |
| 编译员 | 不负责内容正确性，只负责完整与可读       |
| 主编  | 不负责逐字校对，只负责放行判断         |
