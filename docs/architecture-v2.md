# 科研学习自动化工作流 · 架构 v2

> 输入：v1 手绘流程（前端需求 → LLM 联网检索 → 本地仓库 → 总 Agent 调度 → 三子智能体 → 评审 → 排版 → 评审 → 打包）
> 目标读者：科研人员、研究生、高校研究工作者
> 本文只谈结构与边界，不谈具体模型选型；三个已定决策见 §14。
>
> **文档关系**：站点级细化见 `architecture-brief.md`（六站三段），两者冲突时以该文为准；
> 岗位分工见 `agent-roles.md`；5 天双人开发排期见 `build-plan-5d.md`。

## 0. 结论先行

v1 的骨架是对的，问题在于**把三种性质完全不同的工作都画成了 Agent**：

1. 需要判断的（要点提炼、图表解读、内容评审）→ 应该用 LLM
2. 可以精确计算的（跳转链接、去重、格式校验、占位符检查）→ 不应该用 LLM
3. 需要状态与回边的（编排、重试、断点续跑）→ 不应该塞进"总 Agent"

由此得到 v2 的第一原则：

> **Agent 只做判断；凡是能机械判定的，一律下沉为确定性服务。**

这条原则同时解决了 v1 里最危险的两个隐患：
- 「生成跳转链接」由 Agent 承担 → 链接可能指错页，且无法验证
- 两次「评审」都是模型自评 → 没有真正的门禁，只是自我背书

## 1. 痛点 → 架构推论

| 痛点 | 具体表现 | 架构推论 |
| --- | --- | --- |
| 文献检索分散 | 在 Google Scholar、arXiv、出版社站点之间来回跳，重复下载 | 统一入口 + 以 `sha256` 去重的单一事实源；同一篇论文只入库一次 |
| 阅读与摘要耗时 | 20 页论文读 40 分钟，读完记不住数字 | 分层摘要：一句话 / 结构化要点 / 章节级，按需展开而不是一次生成全文 |
| 图表理解困难 | 图注太短，正文里对图的解释分散在三个段落 | 图区域裁切 + 图注 + 引用该图的正文段落，三者拼成一条"图讲什么" |
| 引用溯源不便 | 笔记里写"有研究表明"，回头找不到是哪句 | 锚点对象（论文 + 页码 + 摘句 + 矩形框）贯穿全链，链接只是它的渲染形式 |
| 排版校对成本高 | 手工调格式、核对图号、补引用 | 模板 + 机械校验；排版不由人做，也不由模型自由发挥 |
| 多篇比较无从下手 | 读完五篇，方法差异记混 | 篇级笔记是中间产物，对比是它的归并视图，不重复抽取 |

## 2. 总体架构：四层 + 一条状态机

```
L0 接入层   Web 前端（需求输入 / 项目空间 / 内置阅读器）
              ↓
L1 编排层   Orchestrator：DAG + 状态机 + 预算 + 断点续跑
              ↑（仅当需求模糊时调用一次 Planner 做意图解析）
              ↓
L2 判断层   摘要 Agent │ 图表讲解 Agent │ 对比综述 Agent │ 内容评审 Agent
              ↓
L3 确定层   摄取·锚点 │ 仓库·知识库 │ 模板渲染 │ 机械校验·打包
              ↓
L4 产物层   项目包（index.html + notes/ + figures/ + anchors.json + manifest.json）
```

关键不是分层本身，而是**L2 只占一层**。v1 里 3 个子智能体 + 2 个评审 = 5 个 LLM 角色；
v2 收敛为 4 个能力，且每个都有明确的输入契约与失败语义。

## 3. 模块职责

| 模块 | 输入 | 输出 | 用 LLM | 失败行为 |
| --- | --- | --- | --- | --- |
| Orchestrator | 项目配置、阶段事件 | 任务状态、重试决策 | 否 | 停在当前阶段，保留 checkpoint |
| Planner | 用户自然语言需求 | 任务模板（单篇精读/多篇对比/答疑） | 是，仅一次 | 回退到默认模板"单篇精读" |
| 摄取 | PDF 字节 | 逐页文本、图片区域、元数据、页数、哈希 | 否 | 无文字层→转 OCR 队列；加密/损坏→隔离 |
| 锚点 | 页面文本 + 摘句 | `anchor = {paper_id, page, quote, bbox?, span}` | 否 | 摘句定位失败→降级为"仅页码"，标 `unverified` |
| 仓库·知识库 | 摄取结果 | 去重后的论文、页感知切块、嵌入向量 | 否（嵌入走独立模型） | 嵌入失败不阻塞阅读，标 `embed_pending` |
| 摘要 Agent | 章节文本 + 锚点 | 三层摘要 + 每条要点的锚点 | 是 | 重试 1 次；仍失败→只出抽取式摘要 |
| 图表讲解 Agent | 图区域 + 图注 + 引用段落 | 图讲什么、支撑哪条结论、边界 | 是 | 找不到图注→标 `caption_missing`，不编造 |
| 对比综述 Agent | 多篇笔记 + 各自锚点 | 方法/样本/结论对照表 + 冲突点 | 是 | 少于 2 篇→不启动 |
| 内容评审 Agent | 产物 + 锚点集 | 逐条论断四态 | 是 | 只能降级，不能升级（见 §8） |
| 模板渲染 | 结构化产物 + 模板 | HTML / Markdown | 否 | 占位符缺失→阻断，不出半成品 |
| 机械校验 | 产物 + 锚点 + 源文件 | 可阻断的问题列表 | 否 | 任一条不过→阻断该条并回流 |
| 打包 | 通过校验的产物 | zip + manifest | 否 | 校验清单不完整→拒绝打包 |

## 4. 数据流与状态机

### 4.1 五个一等对象

| 对象 | 说明 | 关键字段 |
| --- | --- | --- |
| `Paper` | 一篇入库论文 | `paper_id`(=sha256 前 10)、路径、页数、DOI、版本 |
| `Anchor` | 一切引用的最小单元 | `paper_id, page, quote, bbox, char_span` |
| `Note` | 篇级结构化笔记 | 三层摘要、要点数组（每条带 anchor_id） |
| `FigureBrief` | 图表讲解 | `figure_id, page, bbox, refers_to[], anchor_ids[]` |
| `Artifact` | 可交付产物 | 路径、模板、评审状态、覆盖范围 |

`Anchor` 是整套设计的枢纽：笔记引用、图表出处、知识库命中、评审校验**共用同一个对象**。
v1 让三个子智能体各自产出内容再拼装，缺的正是这个共同锚点——拼不回去是必然的。

### 4.2 状态机

```
pending → ingested → parsed → extracted → composed → reviewed → rendered → packaged
                                        ↘ needs_review →（人工）→ reviewed
                                        ↘ blocked →（回流到指定阶段）
```

- 每个阶段结束写 `checkpoint.json`（输入哈希 + 输出哈希 + 模型版本 + 提示词哈希）
- 重跑只从失败阶段开始，**不重跑已通过的阶段**
- 状态与文件分离：状态在 SQLite 台账，文件在仓库；台账里记哈希，二者不一致即视为脏数据

## 5. Agent 分工与并行/串行

### 5.1 v1 的分工问题

图上三个 Sub Agent 并列扇出，但实际存在依赖：

- 「图表讲解」需要先知道图区域（摄取产出），且需要正文里引用该图的段落
- 「模板」不是内容，是渲染规则 → 不该是 Agent，应归入 L3
- 「跳转链接」是 `anchor` 的渲染结果 → 不该是 Agent

### 5.2 v2 的依赖图

```
ingest ──┬─→ parse ─→ anchor ─┬─→ notes      ─┐
         │                    ├─→ figures    ─┼─→ compose ─→ review ─→ render ─→ package
         └─→ embed（异步，可晚于交付）        │
                                              └─→ comparison（仅多篇时，依赖 notes 全部完成）
```

- **可并行**：`notes` / `figures`（都只依赖 `anchor`，互不依赖）
- **必须串行**：`compose` 需要三路结果齐全；`review` 在 `compose` 之后；`render` 在 `review` 之后
- **可延后**：`embed` 属于知识库增强，不阻塞本次交付，失败可重试
- **条件启动**：`comparison` 只在项目内 ≥2 篇且用户选择"对比"时启动

### 5.3 为什么不再有"总 Agent 分发"

v1 的总 Agent 同时承担三件事：意图理解、任务分派、结果汇总。这三件事的性质不同：

- 意图理解 → 一次 LLM 调用（Planner），只做"选模板"
- 任务分派 → 确定性 DAG，代码写死，可测试
- 结果汇总 → `compose` 节点，按模板字段合并

把调度交给 LLM 的代价是：不可复现、不可测、失败不可定位。这是 v1 最该砍掉的复杂度。

## 6. 论文入库与知识库衔接

### 6.1 入库

```
上传/检索结果 → sha256 → 已存在？
    ├─ 是 → 复用 paper_id，仅追加来源记录（不重复解析）
    └─ 否 → 落盘 papers/<paper_id>/source.pdf → 解析 → 切块 → 异步嵌入
```

去重键用**文件哈希**而不是 DOI：预印本与正式版 DOI 相同但内容不同，反过来同一 DOI 也可能有勘误版。
DOI 只作辅助索引；版本链记在 `Paper.versions[]`。

### 6.2 知识库切块

- **页感知**：任何 chunk 不跨页，`chunk.page` 必填
- **节感知**：优先按 `Introduction / Methods / Results / Discussion` 切，失败再退回固定长度
- **携带锚点**：`chunk.anchor_ids` 指向页内摘句，检索命中后能直接跳转

### 6.3 衔接方式（避免重复建设）

> **笔记是知识库的视图，不是知识库的副本。**

- 知识库存原文块 + 向量；笔记只存"指向块的引用 + 组织顺序"
- 删除一篇论文 → 其笔记自动失效（外键），不出现"笔记还在、原文没了"
- 检索结果必须带 anchor 才允许进入写作，否则该条结论不能被标为"有据"

## 7. 来源定位与跳转设计

### 7.1 锚点是对象，链接是渲染

```json
{
  "anchor_id": "a_7f3c9b21",
  "paper_id": "p_6b25fd7989",
  "page": 7,
  "quote": "semantic entropy achieves the best AUROC value of 0.790",
  "char_span": [18240, 18295],
  "verified": true
}
```

同一个 anchor 有四种渲染形式，按场景选用：

| 场景 | 渲染 | 说明 |
| --- | --- | --- |
| 包内阅读 | `./pdfs/p_xxx.pdf#page=7` | 浏览器内置阅读器与 Adobe 支持 `#page=`，跳到页但**不框选** |
| 本地原文 | `file:///D:/.../source.pdf#page=7` | 单机场景下最实用；包被移动后失效，manifest 保留绝对路径 |
| 外部文献管理器 | `zotero://select/items/<key>` | 仅在用户装了 Zotero 且已导入时有效 |
| 纯文本降级 | `第 7 页：「semantic entropy achieves...」` | 包被转发、PDF 缺失时的兜底 |

> v2 决策：**不做 bbox 高亮**。锚点保留 `char_span` 字段以兼容将来，但目前只渲染到"页 + 摘句"。

### 7.2 bbox 的取舍（已决策：暂不做）

- **pypdf**：只给文本，不给坐标 → 只能跳到页，不能框选
- **pdfplumber（MIT）**：给逐词 bbox，可自行把"摘句"映射到词框并合并 → 能框选，许可友好
- **PyMuPDF**：`page.search_for(quote)` 直接返回矩形，最省事，但 **AGPL**，分发时需评估

**决策：v2 不引入 bbox。** 理由：高亮是阅读体验的增量，不是链路正确性的前提；
引入 pdfplumber 会让摄取阶段多一个依赖和一次全页布局分析，收益不足以抵消 P0 的复杂度。
锚点结构里保留 `char_span`，将来加 bbox 时只需扩字段，不改协议。

### 7.3 分享场景的现实约束

包被转发后，`file:///D:/...` 一定会断。因此：

- `manifest.json` 记录**原始绝对路径 + sha256**（作者机器可用）
- 包内 `index.html` 优先使用**相对路径**（同目录带 PDF 时可用）
- 两者都不可用时，展示"页码 + 摘句"，并标注"原始文件未随包分发"

不要承诺"任何设备都能跳到原句"——这是 v1 里最容易被忽略的过度承诺。

## 8. 评审规则

### 8.1 三层，职责不重叠

| 层 | 执行者 | 检查内容 | 失败动作 |
| --- | --- | --- | --- |
| R1 机械 | 代码 | 页码存在、摘句能否在该页定位、每条要点是否带 anchor、图片文件是否存在、模板占位符是否填满、字数上限、引用编号连续性 | **阻断该条**，回流到产出它的阶段 |
| R2 模型 | 内容评审 Agent | 论断是否有原文支撑、是否把综述写成实验、数字是否与原句一致、类比是否标注、是否越界推断 | 标 `needs_review`，不阻断，进人工队列 |
| R3 人工 | 人 | 抽检 10% + 全部 `needs_review` 项 + 打包前终审 | 退回指定阶段，记录确认人与理由 |

### 8.2 一条硬规则

> **模型评审只能降级，不能升级。**

即：R1 判失败的内容，R2 无权判通过；R2 只能把 `supported` 降为 `needs_qualification`。
否则"再审一次"就变成了"换个模型说好话"，门禁失去意义。

### 8.3 v1 的两次评审怎么处理

不是两个 Agent，而是**一个评审服务、两套判据、两个挂载点**：

- 挂载点 A（compose 之后）：判内容——事实、越界、数字、类比
- 挂载点 B（render 之后）：判成品——结构完整、图号连续、目录可跳、样式占位符无残留

两次都调同一个 `review(artifact, criteria)`，只是 `criteria` 不同。这样避免维护两套提示词与两套输出协议。

### 8.4 回流路径（v1 完全缺失）

每条问题必须带 `target_stage`：

| 问题类型 | 回流目标 | 重跑范围 |
| --- | --- | --- |
| 摘句定位失败 | `anchor` | 该条 anchor |
| 要点无原文支撑 | `notes` | 该篇笔记 |
| 图注缺失 | `figures` | 该图 |
| 占位符残留 / 图号断号 | `render` | 整篇渲染 |
| 结构缺节 | `compose` | 该篇组合 |

重试上限 2 次；超限转人工队列，并把失败上下文（提示词、原始输出哈希、校验结论）一并存入 `blocked/`。

## 9. 异常处理

| 异常 | 检测点 | 处理 | 用户可见状态 |
| --- | --- | --- | --- |
| 扫描件无文字层 | ingest | 转 OCR 队列，不进入抽取 | `ocr_pending` |
| PDF 加密 / 损坏 | ingest | 隔离到 `quarantine/` | `rejected` + 原因 |
| 同一论文重复上传 | ingest | 哈希命中，复用 | `duplicate`（显示已有笔记入口） |
| 模型限流 / 超时 | 任意 LLM 节点 | 指数退避 3 次，失败则停在该节点 | `failed` + 可续跑 |
| 摘句定位失败 | anchor | 降级为"仅页码" | `unverified`（不阻断整篇） |
| 预算超限 | orchestrator | 停在当前阶段，出部分结果 | `partial` + 已花费 |
| 评审冲突（R1 过、R2 不过） | review | 以 R1 为准，R2 降级 | `needs_review` |
| 嵌入失败 | embed | 不阻塞交付 | `embed_pending` |

原则：**宁可出"部分结果 + 明确缺口"，不出"看起来完整但没有出处"的成品。**

## 10. 打包格式

```
<project>-<yyyyMMdd>.zip
├── index.html              离线可读，含目录、锚点跳转、评审结论角标
├── notes/
│   └── p_6b25fd7989.md     篇级笔记（Markdown，锚点以 [#a_7f3c] 标记）
├── figures/
│   └── p_6b25fd7989/
│       ├── p07-fig2.png    按页裁切的图
│       └── p07-fig2.md     讲解（讲什么 / 支撑什么 / 边界）
├── anchors.json            全部锚点（页码、摘句、字符偏移、verified）
├── manifest.json           来源、哈希、模型、评审、覆盖范围
└── assets/                 CSS、字体、缩略图
```

`manifest.json` 必填字段：

| 字段 | 用途 |
| --- | --- |
| `project` / `generated_at` | 版本与时间 |
| `papers[]`：`sha256`、`doi`、`pages`、`source_path` | 证明"基于哪一版原文" |
| `artifacts[]`：`path`、`sha256`、`stage`、`review_status` | 证明"哪些内容过了哪一层" |
| `model`：名称、版本、`prompt_hash` | 复现生成条件 |
| `coverage`：已审段落数、`unverified` 条数、未覆盖页 | 明确"哪里没做到" |
| `human_signoff`：人名、时间、抽检比例 | 责任可追溯 |

不把 PDF 打进包（版权），但记录路径与哈希；用户可选"附带 PDF"开关。

## 11. 设计点 → 痛点 对照

| 设计点 | 解决的痛点 | 机制 |
| --- | --- | --- |
| 单一事实源 + 哈希去重 | 检索分散、重复下载 | 一篇论文只解析一次，所有产物共享 |
| 三层摘要 | 阅读耗时 | 按需展开，不逼用户先读 2000 字 |
| 图区域裁切 + 引用段落聚合 | 图表看不懂 | 把图、图注、正文解释放在同一屏 |
| 统一 anchor | 溯源不便 | 一处生成，四处复用（笔记/图/检索/评审） |
| 机械校验前置 | 校对成本 | 结构性错误由代码拦，人只看内容判断 |
| 模板渲染（非 Agent） | 排版成本 | 排版是确定性变换，可回归测试 |
| 模型评审只降级 | 自评失效 | 门禁强度不被"再审一次"稀释 |
| 断点续跑 + 逐阶段 checkpoint | 重跑浪费钱 | 只重跑失败节点 |
| 分层交付（L0 入库 / L1 速览 / L2 精读） | 成本不可控 | 不读全文也能先建库，按需付费 |

## 12. 从 v1 删掉的东西

| 删掉 | 原因 | 替代 |
| --- | --- | --- |
| 「生成跳转链接」Sub Agent | 链接是索引，不是内容；LLM 生成会指错且不可验 | `anchor` 服务 + 四种渲染 |
| 「生成模板」Sub Agent | 模板是静态资产，不是每次生成 | `templates/` + 渲染器 |
| 两个评审 Agent | 判据不同但协议相同，维护两套是浪费 | 一个 `review()`，两套 criteria |
| 总 Agent 的"分发" | LLM 调度不可复现、不可测 | DAG 编排 + 一次 Planner |
| 本地仓库作为"旁挂缓存" | 缓存与事实源混在一起，删了不知道会不会坏 | 升为唯一事实源，笔记本体只是视图 |

---

## 13. 分期落地

| 期 | 范围 | 验收标准 |
| --- | --- | --- |
| P0 | 摄取 + 锚点 + 篇级笔记 + 机械校验 + Markdown 打包 | 摘句定位率、每条要点都有 anchor |
| P1 | 图表裁切与讲解 + HTML 渲染与页内跳转 + 内容评审 | 图号连续、跳转可用、评审可降级 |
| P2 | 知识库嵌入 + 多篇对比 + 人工复核回写 | 检索命中能回跳、对比表可导出 |

每一期都能独立交付，不依赖下一期。这是"避免无效环节"的工程保证：任何一期停下来，产物都是可用的。

## 14. 已定决策

| 决策 | 取值 | 理由 | 对实现的影响 |
| --- | --- | --- | --- |
| 主产物 | **单篇精读包** | 单篇是高频动作，多篇对比天然建立在篇级笔记之上；先做实下层，上层才不是空中楼阁 | DAG 为线形，`comparison` 节点留空实现，仅保留接口 |
| 部署 | **本地单机** | 无账号、无租户、无并发控制；SQLite + 本地目录即可 | 会话与权限层不做；PDF 用绝对路径 `file://` 跳转可行 |
| 高亮 | **暂不做 bbox** | 高亮是阅读体验增量，不是链路正确性前提；多一个依赖会拖慢 P0 | 锚点保留 `char_span`，渲染到"页 + 摘句"；将来扩字段即可 |

三条决策共同确定了一个形态：**一次一篇，跑完出包，双击 `index.html` 就能读**。
后续如果要转多篇或团队共享，改动集中在 `comparison` 节点与存储层，不触碰锚点协议与评审规则。
