# 科研精读工作流 · 架构简版

> 本文是 `architecture-v2.md` 的精简版与站点级细化。两者冲突时，以本文的**六站**为准。
> 一句话定位：把一篇论文编译成一组**带边界、可回查的论据卡**，再打包成可交付的精读包。

---

## 1. 三段六站

```
① 地基（代码）      ② 取证（模型，三站并行）           ③ 裁决（代码优先）
┌──────────┐      ┌────────┬────────┬────────┐      ┌────────┬────────┐
│  S1 拆解  │ ──→ │ S2 取证 │ S3 质疑 │ S4 划界 │ ──→ │ S5 对账 │ S6 编译 │
└──────────┘      └────────┴────────┴────────┘      └────────┴────────┘
   PDF→可定位文本        支持卡    反证卡    条件卡         门禁       精读包
```

| 段 | 站 | 这一步的作用 | 输入 → 输出 | 谁判定 | 失败怎么办 |
| --- | --- | --- | --- | --- | --- |
| ① 地基 | **S1 拆解** | 把 PDF 变成"可定位"的文本：逐页文字、图表区域、元数据、页码索引。**不预生成锚点**——此时还不知道要引哪句 | PDF → `pages[]` + 元数据 | 代码 | 无文字层转 OCR 队列；加密/损坏隔离进 `quarantine/` |
| ② 取证 | **S2 取证** | 抽出作者的主张（方法、结果、数字），逐条回查原句，**首次给出 quote 时物化锚点** | 页文本 → `Anchor[]` + `ClaimCard[]`（支持） | 模型抽 + 代码回查 | 定位不到即标 `unverified`，不进入后续写作 |
| ② 取证 | **S3 质疑** | 专门抽取作者想让你略过的东西：局限、反常结果、未解释现象 | 讨论/局限段 → `ClaimCard[]`（反证） | 模型抽 + 存在性检查 | 抽不到就标 `missing`，禁止编造 |
| ② 取证 | **S4 划界** | 抽出结论的适用条件：样本、人群、任务、模型、数据集、时长、剂量，并给出"可用句式" | 方法/结果段 → `ClaimCard[]`（条件） | 模型抽 + 清单校验 | 一个维度都没有则标 `scope_unknown` |
| ③ 裁决 | **S5 对账** | 先跑机械校验（引文能否定位、页码是否存在、字段是否齐全），再让模型复核事实与越界；产出三态门禁 | 全部卡片 + 原文 → 报告 + 路由 | 代码优先，模型只能降级 | 任一条不过 → `blocked/`，带 `target_stage` 回流 |
| ③ 裁决 | **S6 编译** | 把通过门禁的卡片渲染成 HTML/Markdown，打包 zip，写 manifest（来源哈希、模型版本、覆盖范围） | 卡片 → 精读包 | 代码 | 占位符缺失 → 拒绝打包 |

**为什么是这三段**：两端确定性，结果可复现；中间三站都是"读同一份已定位的文本"，所以能并行；交汇处设门禁，机器能判的先判，判不了的才交给人。

**每站绑定一个模型角色，不共用同一个模型**（见 `model-routing.md`）：

| 站 | 角色 | 档位 | 失败降级 |
| --- | --- | --- | --- |
| S2 取证 | `evidence` | 便宜、长上下文 | → 强模型 |
| S3 质疑 | `challenge` | 强推理、温度偏高 | → 强模型 |
| S4 划界 | `scope` | 便宜、温度 0 | → 强模型 |
| S5 评审 | `audit` | **与写作不同的那家** | → 强模型 |

评审必须与生成异构：同一模型自评，会用相同的偏好放过相同的错误。

## 2. 四个数据对象

| 对象 | 是什么 | 关键字段 | 谁生产 |
| --- | --- | --- | --- |
| `Paper` | 一篇入库论文 | `paper_id`(=sha256 前 10)、页数、原文路径 | S1 |
| `Anchor` | 引用的最小单元 | `anchor_id`、`page`、`quote`、`char_span`、`verified` | S2（首次出现摘句时） |
| `ClaimCard` | 论据卡 | `claim`、`kind`(support/counter/scope)、`status`、`conditions[]`、`anchors[]` | S2/S3/S4 |
| `Artifact` | 可交付产物 | 路径、模板、评审状态、覆盖范围 | S6 |

锚点是全链唯一的"回退凭证"：卡片引用它、评审核对它、打包渲染它。**没有锚点的句子，不得成为论据。**

---

## 3. 数据流

```
PDF ─S1─→ pages + 页码索引 ─┬─S2─→ 锚点 + 支持卡 ─┐
                           ├─S3─→ 反证卡 ────┼─S5─→ 门禁 ─S6─→ zip(index.html / notes / anchors.json / manifest.json)
                           └─S4─→ 条件卡 ─┘         │
                                                    └─ blocked/（诊断 + target_stage）
```

一次运行 = 一份论文 + 一条项目记录。同一份 PDF 第二次进入时复用 S1 结果，不重复解析。

---

## 4. 三条铁律
1. **没有通过回查的句子，不能成为论据。** 回查是机械的：摘句必须能在该页原文中逐字定位。
2. **模型评审只能降级，不能升级。** 机械校验判失败的内容，模型无权判通过。
3. **宁可出"缺口 + 说明"，不出"看起来完整但没有出处"的成品。** manifest 必须写明覆盖范围。

---

## 5. 不做什么（本版边界）

| 不做 | 原因 |
| --- | --- |
| 多篇对比、综述生成 | 单篇都没做扎实，多篇只会放大错误 |
| PDF 内高亮框选 | 需要 bbox，多一个依赖；先做到"跳到页 + 摘句" |
| 团队协作与权限 | 本地单机，无账号体系 |
| 全自动无人工 | 门禁留人工卡点；`needs_review` 必须有人看过 |
| 论文查重、翻译、润色 | 不属于"论据编译"这条链 |

## 6. 知识库模式（可选，见 `knowledge-base.md`）

单篇精读解决"读透一篇"，但写论文需要"在几百篇里找到该引的那几句"。知识库不是第七站，而是**一层服务 + 一个前置站 S0**：

| 级别 | 成本 | 产出 | 能否引用 |
| --- | --- | --- | --- |
| L0 索引 | 0 次模型调用 | 页文本、切块、向量、元数据 | 否，只能"找到" |
| L1 速览 | 1 次/篇 | 一句话主张 + 5 条要点 | 否，判断是否精读 |
| L2 精读 | 六站全跑 | 论据卡 + 审计 | **是，唯一可引用** |

```
批量 PDF → L0 全量索引 → S0 检索（我要论证 X）→ 候选 20 篇
        → L1 速览 → 勾选 5 篇 → L2 精读 → 论据矩阵 → 综述包
```

新增只影响三处：**S0 检索**（新站）、**S5 对账**（加跨篇冲突规则）、**S6 编译**（加矩阵页与引注表）。其余五站不变。
